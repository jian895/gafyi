第二章一把锁

微信给 AI 开了一扇门，但只有一把钥匙。

微信的 ClawBot 能把消息交给程序处理，可它一次只认一个程序。谁在轮询，消息就归谁。

接上 Grok，Muse 就收不到；换成 Muse，Grok 又断了。

POST /ilink/bot/getupdates   # grok 在等
200  { msgs: [ "帮我查库存" ] }

POST /ilink/bot/getupdates   # muse 也在等
200  { msgs: [ ] }   # 消息已被 grok 取走
第三章一个 @

于是，G@ 站到了门口。

G@ 独自握住那把钥匙。你 @ 的是谁，它就把信交给谁，回信再原路带回来。智能体不需要公网地址，每个只拿一条属于自己的链接。

第五章造它的方式

轻到你会忘了它在运行。

G@ 是一个 Go 写的单文件程序，跑在你自己的服务器上。消息不经过任何第三方中转。

1个文件单个二进制，没有依赖，没有数据库
≈10MB常驻内存
<1秒从微信到智能体的转发耗时
AES128图片和文件按需解密，不落盘
25MB单个文件收发上限
MIT开源许可，随便改，随便用
第六章名字

为什么叫 G@

G
Gateway，网关。站在微信和智能体之间的那一道门。
@
你唯一需要学会的操作。@ 的中心本来就是一个 a，所以 G@ 念作 ga，像消息落地的那一声「嘎」。
●
@ 的外圈没有闭合，缺口里那颗金色的点，是你刚刚送出的那条消息。

今晚，
接上你的第一个智能体。

准备一台有 HTTPS 的服务器。部署好之后打开后台，扫码绑定微信，选一个智能体，把专属话术发给它。它连上的那一刻，你的微信会收到一条通知。

部署 · Linux
# 编译安装（需要 Go 1.22+）
$ git clone https://github.com/jian895/gafyi.git && cd gafyi
$ make build && sudo install -m 755 gafyi /usr/local/bin/

# 生成后台密钥，写进 /etc/gafyi/config.json
$ gafyi genkey

# 作为系统服务运行，然后打开 <public_url>/admin
$ sudo cp deploy/gafyi.service /etc/systemd/system/
$ sudo systemctl enable --now gafyi
